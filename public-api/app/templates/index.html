Getting a slow upstream's answer past a gateway timeout

The public API answers 202 Accepted right away, then calls a slow upstream agent. The upstream sits behind its own gateway, which behaves like Cloudflare: it drops any connection that stays silent for {{ edge_timeout | round(0) | int }}s. Run the four scenarios side by side to see which ones get their answer back.

Who has to send the keep-alive? The upstream. The gateway only resets its timer when bytes arrive from the upstream, so nothing the caller sends helps. What the caller can do: choose streaming, check that the upstream sends keep-alives during its longest silence, or turn on options that make it send progress (the fourth scenario). If none of that works, use the upstream's async API if it has one.
